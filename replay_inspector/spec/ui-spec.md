# 個性化搜尋事件回放器 · UI 規格

> 搭配 `spec/v1-spec.md`（資料與領域邏輯）閱讀。本檔只管畫面。
> 最後更新：2026-08-18

---

## 1. 設計命題

這個介面只有一個工作：**讓人分辨訊號與雜訊。**

使用者盯著兩欄幾乎一樣的數字，要判斷「treatment 和 control 的差異是真的，還是浮點噪音」。前十名的 `ltr_score` 只差 7–15 個 float32 ULP —— 大部分位置變動都沒有意義。

所以整套視覺系統編碼的不是「類別」，而是**可信度**。

### 1.1 核心決定：把顏色留給有意義的事

五種判讀狀態如果都給飽和色，畫面會變成彩紙屑，什麼都讀不出來。因此：

| 狀態 | 是否值得查 | 視覺 |
|---|---|---|
| `only_a` / `only_b` | **是** — 個性化的實質證據 | 唯一有色（teal / ochre） |
| `real_move` | 是 — 跨同分帶的真實變動 | 深墨色，加重 |
| `tie_unresolvable` | 否 — 浮點噪音 | 灰，主動後退 |
| `identical` | 否 | 極淡，近乎消失 |
| 品質異常 | 是 | 深紅，僅用於旗標區 |

不可判讀的東西要在視覺上**主動退場**，不是中性顯示。這是本設計最重要的一條，違反它整個工具就失去價值。

## 2. 設計方向

參考的視覺世界是**計量學（metrology）**：公差帶、量規、標稱值與偏差。這剛好是這個工具在做的事 —— 判斷兩個測量值的差異是否超出量測不確定度。不是儀表板，是量測報告。

### 2.1 色彩

```css
--paper:      #F4F6F5;  /* 底，帶極淡冷綠，近圖表紙 */
--surface:    #FFFFFF;  /* 卡片 */
--ink:        #16191A;  /* 主文字、真實變動 */
--graphite:   #616A6B;  /* 次要文字、不可判讀 */
--faint:      #9AA3A3;  /* 一致、佔位符 */
--rule:       #D5DAD9;  /* 髮線、燈號零值 */
--tolerance:  #E9EDEC;  /* 同分帶底色 */
--measure:    #0B5D5A;  /* A / treatment — 深青 */
--counter:    #8A5A12;  /* B / control — 赭黃 */
--alert:      #A32B24;  /* 品質異常 */
```

青／赭這組配對取代常見的紅／綠：紅綠對色弱使用者不可辨，而這個工具的 A/B 對照是全畫面最頻繁的判讀動作。青與赭在明度與色相上都可分辨。

`--alert` 只用於品質旗標區與強度警示，**不用於排序表**。排序表裡沒有「錯」，只有「可判讀」與「不可判讀」。

### 2.2 字體

IBM Plex 超家族，三個角色：

| 角色 | 字體 | 用途 |
|---|---|---|
| 標籤 | `IBM Plex Sans Condensed` 500 | 欄位名、eyebrow、旗標 |
| 內文 | `IBM Plex Sans` 400/500 | 判讀文字、說明、空狀態 |
| 數值 | `IBM Plex Mono` 400/500 | 所有數字、ID、程式碼 |

選它是因為 Plex 為技術介面而設計，且三個變體同源、字寬一致。中文以 `Noto Sans TC` 承接。

**數值一律 `font-variant-numeric: tabular-nums`。** 這個介面的內容就是垂直比較數字，等寬數字不是偏好而是功能需求。

字級（4px 基準）：

```
readout 數值   26px / 1.1  Mono 500
標題          15px / 1.4  Sans 500
內文          13px / 1.5  Sans 400
表格數值      12.5px / 1  Mono 400
表格判讀      12px / 1.4  Sans 400
標籤          11px / 1.2  Condensed 500，字距 0.06em（僅拉丁與數字）
註腳          10.5px / 1.3 Condensed 400
```

字距只套用在拉丁字母與數字上。**中文不加字距**，會散掉。

### 2.3 有效位數強調

`110.996254` 這串字裡，`110.99` 是所有商品共有的，不帶資訊。共同前綴用 `--faint`，差異部分用 `--ink`：

```html
<span class="score"><span class="prefix">110.99</span>6254</span>
```

前綴長度在渲染時由當前可見列的最長共同前綴決定，不要寫死。這條規則讓使用者的眼睛直接落在唯一有資訊的位數上。

## 4. 標題列

單行。左側是**當前查詢的自然語言摘要**，不是欄位名：

```
福岡   zh-tw · tw   2026-08-13 (UTC+8)   A treatment 100000 ↔ B control 100001
```

日期必須永遠標註 `(UTC+8)`。底層 `event_date` 是 UTC，這個時區落差是真實會導致查不到資料的坑，標註不是禮貌而是防呆。

展開條件列後的欄位順序：日期 → keyword → locale/lang → 實驗組 A/B → 進階（收合：kkud、member_uuid、session_id、cache_hit）。

### 4.1 右側常駐資訊（2026-08-27 追加）

標題列右側固定顯示三個元素，由左至右：

```
搜尋巡檢平台 ↗   Query Project kkday-data-dap-ui   搜尋事件回放
```

- **「搜尋巡檢平台 ↗」**：跟主平台互開新分頁的入口（主平台 `AppHeader` 的「回放」
  連結是反方向）。樣式跟資料格連結（`.pname`，虛線底線）刻意區隔——這是導覽用的
  按鈕感連結，用 `.ri-navlink`（無底線，hover 淺灰底），不是資料值
- **「Query Project kkday-data-dap-ui」**：這個工具打 BigQuery 的計費 project，
  不用等查詢完就看得到帳單打去哪裡（跟主平台 backend 用的 `-sit` 是不同 project，
  這條紅線見 `CLAUDE.md` 紅線 1/4）
- **「搜尋事件回放」**：原有的 app 名稱 eyebrow 標籤，不變

日期欄位（§4 條件列展開後）改用瀏覽器原生月曆選擇器（`st.date_input`），預設值是
開啟畫面當下的日期，不再要求手動打字（原本的純文字輸入容易打錯格式）。

### 4.2 用量顯示（2026-08-27 追加）

單人回放與兩組對照模式的身分摘要列（§6.2 之前的識別資訊列）都加一段用量文字：

```
單人回放 — 使用者只歸屬一個實驗組，無 A/B 對照；本頁 10 筆 · 全量 581 筆 · rank ≤ 100 進精排 · 用量 64.6 GB
```

數字是這次載入畫面真正花掉的 BigQuery 計費位元組數（`last_query_bytes()` 加總，
不是預估值），單位依大小自動換算 B/KB/MB/GB。這不是可判讀的訊號燈號（不套色彩紀律
的警示色），純粹是給人核對成本用的參考數字。

## 5. 讀數列（signature 之外的第二重點）

四個數字，不加圖表、不加趨勢線、不加 sparkline。

| 讀數 | 來源 | 上色規則 |
|---|---|---|
| 個性化強度 | `1 − overlap/10` | < 5% → `--alert`；> 60% → `--counter`；其他 `--ink` |
| Top10 重疊 | `8/10` | 恆 `--ink` |
| 跨帶變動 | `real_move` 計數 | 恆 `--ink` |
| 同帶內位移 | `tie_unresolvable` 計數 | 恆 `--graphite`（刻意灰） |

「同帶內位移」用灰色，即使數字很大。它是提供給使用者的**扣除項**，不是成績。

強度觸發門檻時，讀數下方加一行 11px 說明：

- < 5%：`兩組結果幾乎相同，個性化可能未生效`
- \> 60%：`兩組差異偏大，注意長尾商品曝光`

## 6. 排序對照表（signature）

### 6.1 同分帶括號

**這是整個介面的記憶點。** 同一同分帶的列用左側一道垂直軌線包起來，軌線兩端向內收 —— 視覺上先讀到「這幾列是一組」，才讀到文字。位置在括號內對調，一眼就知道不必追查。

規則：

- 軌線寬 2px，`--graphite` 30% 透明，距列左緣 8px
- 該帶所有列底色 `--tolerance`
- **單筆成帶不畫括號**（沒有東西要群組），底色也不上
- 帶與帶之間插入一列分隔，高 24px，內容為髮線加標籤：
  ```
  ── 帶邊界 · Δ2.7e-4 ≈ 36 ULP ──
  ```
  標籤 10.5px Condensed `--graphite`，居中。分隔線 `--rule`

分隔列上的間距值是**這個分組成立的理由**，必須顯示。使用者要能反駁 QA 的判讀，就得看到門檻。

### 6.2 欄位

| 欄 | 寬 | 內容 |
|---|---|---|
| A | 32px | treatment 排名，缺值 `—` |
| B | 32px | control 排名，缺值 `—` |
| prod_mid | 76px | Mono。`prod_oid` 與其相同時不顯示 |
| 分數 | 92px | 依 §2.3 前綴淡化。`in_rerank_scope=false` 顯示 `未進精排`（Condensed，`--faint`） |
| 相關性 | 62px | 六格燈號，見 6.4 |
| 判讀 | 剩餘 | 文字，見 6.3 |

列高 34px。髮線分隔 `--rule` 0.5px。

**不設 Δ 欄。** 見 §12.1。

### 6.3 判讀欄

純文字，不用圖示。圖示需要圖例，文字不用。

| 狀態 | 文字 | 樣式 |
|---|---|---|
| `only_a` | `僅 A 前 10` | `--measure`，列左緣 3px `--measure` 實心條 |
| `only_b` | `僅 B 前 10` | `--counter`，列左緣 3px `--counter` |
| `real_move` | `跨帶 ↓3` | `--ink` 500 |
| `tie_unresolvable` | `同帶內位移` | `--graphite` 400 |
| `identical` | `—` | `--faint` |

#### 差異位後綴

基礎文字後可接六碼差異位，例：`跨帶 ↓3 · ④ 差異`。

**觸發條件只有一個：兩側皆有六碼，且碼不同。** 因此只可能出現在 `real_move` 與 `tie_unresolvable`。

`tie_unresolvable` 也接後綴是刻意的：分數落在同帶內代表排序不可判讀，但六碼不同代表相關性維度確實不一樣。這是唯一一種「可以忽略排序、但不該忽略該列」的情況。顏色仍維持 `--graphite`，不因為多了資訊就加重。

#### `only_*` 不接差異位

`only_*` 的定義就是對側沒有這筆，**沒有可比對象，差異位不存在**。不要用任何方式補上（不要拿本側的碼當差異、不要拿共同商品的眾數當基準）。該列的六碼由燈號欄呈現，就在同一列，文字重述沒有增益。

#### 為什麼是「前 10」而不是「僅 A」

`only_*` 是在 **top-10 視窗內**判定的，不是完整結果集。`total_count` 常達數百，而 `search_event_prod_daily` 只落了 content 事件實際曝光的那一頁。一筆在 A 排第 6 的商品，在 B 可能排第 340 —— 查不到不等於不存在。

寫「僅 A」會讓人誤判成召回端有差，實際上可能只是被排到後面。文案必須保留視窗限定詞。同理，讀數列的指標名稱是「Top10 重疊」而非「重疊」。

### 6.4 相關性六格燈號

六個 7×14px 圓角 1px 方塊，間距 2px。左至右對應：可售 / 地點 / 類目 / IP / 主題 / 文本。

值到填色的映射：

```
0 → var(--rule)
1 → ink 25%    2 → ink 50%    3 → ink 75%    ≥4 → ink 100%
```

**第 4 格（IP）語意未確認**（見 `v1-spec.md` §9.1）。在確認前：該格上緣加 1px 虛線標記，hover 提示 `IP 維度語意待確認`。若確認為使用者地理，改用 `--measure` 色階 —— 因為那將是六碼中唯一的 user × 商品維度，需要與其他五格區分。

解碼失敗（非六位數字、null）→ 六個空心框加一個 `?`，`--faint`。**不猜值、不留空白**。

hover 顯示原始碼與逐位數值：`000220 · 可售0 地點0 類目0 IP2 主題2 文本0`

### 6.5 精排邊界

當可見列跨越 rank 100，插入一列全寬分隔：

```
── 精排邊界 · 第 101 名之後無 ltr_score，個性化不生效 ──
```

樣式同帶邊界但標籤色 `--counter`。若整頁都在邊界外，改在讀數列下方顯示同一段文字，並將個性化強度顯示為 `不適用`。

### 6.6 廣告

`is_ad = true` 的列在 prod_mid 後加 11px Condensed 標籤 `AD`，`--counter`。不改列底色。

## 7. 特徵側欄

順序固定：**串接品質 → uf → cf**。品質在最上面，因為它決定下面的數值能不能信。

### 7.0 事件選擇跟本側欄脫鉤（2026-08-27 追加）

「選哪一筆事件」的下拉選單固定顯示在查詢按鈕正下方（§4 條件列與 §5 讀數列之間），
**不**跟著本側欄的收合/展開狀態走。原本藏在收合的側欄 container 裡，Streamlit
的 container 定位規則會把它排到整張排序表下面——使用者要滑到頁尾才看得到，也不
知道有其他分頁可選（492 筆全量裡，回放器只看得到真的被請求過的那幾頁，找不到選單
等於這個能力不存在）。

下拉選項標籤格式：`exp {實驗版本} · 排名 {該頁涵蓋的排名區間} · {live/cache} ·
{事件發生時間 HH:MM,UTC+8} · {session_id 前 8 碼}`，每段都標籤化，`live`/`cache`
沿用 §7.1 品質旗標同一套詞彙，不用 `content`/`content.cache` 這種原始 event_type
值（第一版標籤 `130010 · #1~10 · content · c687e3b5-2330-4f60` 使用者反饋看不出
哪段是什麼，已改版）。

### 7.1 串接品質

三個旗標橫排，11px Condensed：

| 旗標 | 通過 | 未通過 |
|---|---|---|
| `join_failed` | `✓ recall 已串接` | `✕ 串不回 recall` `--alert` |
| `uf_absent` | `✓ uf 存在` | `⚠ 上游未推 uf` `--counter` |
| `ltr_features_recovered` | `✓ ltr 原生` | `⚠ ltr 由 cache 回收` `--counter` |

`join_failed` 為真時，下方整個 uf/cf 區塊 `opacity: 0.4` 且不可展開，並在旗標下加一行：`串不回 recall 事件，因此沒有特徵資料。排序仍可判讀。`

### 7.2 uf 三列

每列：名稱（Condensed）＋ 覆蓋率徽章 ＋ 數值（Mono 12px）。

覆蓋率徽章必須與數值並列。實測基準 `intent 63.5%` / `profile 54.0%` / `lbs 20.3%`。使用者看到空白時要能立刻判斷這是常態還是異常 —— 20% 覆蓋的欄位空白很正常，54% 的空白就值得查。徽章 < 30% 時加空心圓 `○` 作低覆蓋提示。

無值顯示 `本筆無資料`，`--faint`。不顯示 `null`、不留空。

### 7.3 cf

摘要 chips：`web` · `15時` · `週四` · `query.final 福岡` · `tokens [福岡]`。

底部按鈕：`展開完整 cf（138 KB）`。點擊才呼叫 API。**完整 cf 絕不隨列表載入。**

## 8. 狀態

### 8.1 空狀態

錯誤與空狀態要指出下一步，不道歉、不含糊。

| 情境 | 文案 |
|---|---|
| 未選日期 | `選一個日期才能查詢。` |
| 查無事件 | `08-13 的「福岡」在 zh-tw 沒有 content 事件。試著放寬 locale，或換一天。` |
| 找不到 control | `找不到 control 組事件，無法計算個性化強度。可改用兩個裝置對照。` |
| 條件不足 | `keyword、kkud、member_uuid、session_id 至少填一項。` |
| 查詢過大被擋 | `這個條件的掃描量超過上限。縮小時間範圍或加上 keyword。` |

### 8.2 載入

排序表顯示 8 列骨架（`--tolerance` 底色的空列），讀數列顯示 `—`。**表格區不用轉圈動畫** —— 骨架已經傳達了結構，轉圈只是多餘的動態。

### 8.3 動態政策

只有兩處動態：

1. 列 hover 底色轉場 120ms
2. 側欄展開/收合 160ms `ease-out`

其他一律靜態。這是量測報告，動態會暗示有變化 —— 而這個畫面的主張正好相反：大部分東西沒有變化。`prefers-reduced-motion` 時兩項都關閉。

### 8.4 品質底線

- 響應到 375px 寬可用
- 鍵盤焦點可見，`--measure` 2px outline
- 表格用真 `<table>` 加 `<th scope>`，判讀狀態不能只靠顏色（文字已承載語意，符合）

## 10. 反模式

以下每一項都是「看起來更完整但會讓工具失效」的做法：

- **在 `tie_unresolvable` 列顯示 `Δ = -1`。** 這是本專案最主要的誤導來源。同帶內沒有 Δ 可言
- **用紅／綠表示排序上升下降。** 對色弱不可辨，且暗示「好／壞」——排序變動本身沒有好壞
- **每一列都上色。** 顏色一旦普及就失去指示功能
- **只用圖示表示判讀狀態。** 五種狀態的圖示需要圖例，文字不用
- **在排序表加 sparkline 或分數微條。** 同分帶括號已經承載了離散度資訊，微條是重複
- **在 `only_*` 列補出差異位。** 對側沒有六碼，任何補法都是編造。見 §6.3
- **把 `only_*` 寫成「僅 A」而省略「前 10」。** 這是 top-10 視窗內的判定，不是完整結果集
- **把覆蓋率藏進 tooltip。** 它是判讀空白值的必要條件，必須常駐
- **顯示 `null` 或空白格。** 一律用明確文案（`本筆無資料` / `未進精排` / `?`）
- **在列表載入完整 `cf`。** 138 KB × 列數
- **把 `ip`、`member_uuid` 放進 URL。**

## 11. 驗收

1. `only_*` 列不含差異位後綴，且文案帶「前 10」限定詞
2. 前十筆同分時，判讀欄顯示「同帶內位移」，且該區有可見的括號與底色
3. 帶邊界列顯示實際間距值與 ULP 換算
4. 全畫面只有 `only_a` / `only_b` / 品質旗標 / 強度警示帶顏色
5. 分數欄共同前綴為淡色，且前綴長度隨可見列變化
6. 六碼解碼失敗顯示 `?`，不顯示空白或 `null`
7. 第 4 格燈號在語意確認前帶虛線標記
8. `join_failed` 時特徵區置灰且不可展開
9. 覆蓋率徽章與特徵值同列可見，未藏於 tooltip
10. 375px 寬可用，`prefers-reduced-motion` 下無轉場
11. 完整 `cf` 只在點擊後載入
